# 유튜브 숏폼 대본 (content.youtube.script)

먼저 `common.md`. 참고: smartdong-2team/blog2shorts 장면 구조(hook·body·cta), 해요체, 자막 분할 방식.

## 형식
```json
"youtube": {
  "title": "…#shorts", "description": "…", "tags": ["…"],
  "script": {
    "pronounce": {"GAUDO": "가우도"},
    "scenes": [
      {"photo": "cover", "role": "hook", "narration": "다리를 걸어서만 들어갈 수 있는 섬, 강진 가우도예요."},
      {"photo": "P001", "role": "body", "narration": "…", "subtitle": "선택 — 화면 자막을 다르게 쓸 때만"},
      {"photo": "P005", "role": "cta", "narration": "…"}
    ]
  }
}
```
- `photo`: `"cover"`(컨펌된 인스타 표지 카드, 첫 장면 권장) 또는 사진 ID. 사진은 `selection.json`의 `shorts` 순서대로만 쓴다(점검 항목). 장면마다 다른 사진.
- `role`: 첫 장면 `hook`, 마지막 `cta`, 나머지 `body`.
- 장면 4~7개, 내레이션 합계 120~180자 → 약 20~28초(규칙 15~30초). 장면 길이는 TTS 실제 길이로 자동으로 정해진다.
- `subtitle`은 화면 글자를 짧게 줄이고 싶을 때만 쓴다. **문장 수가 narration과 같아야 하고 뜻이 같아야 한다.**
- `pronounce`: 영어·약어를 TTS가 이상하게 읽으면 발음을 적는다(자막에는 원문). 숫자·단위(2.5km, 1시간, 1~2월)는 스크립트가 자동으로 읽기 쉽게 바꾼다.

## 대본 쓰기
- 블로그 글을 줄이지 말고 **말로 들려줄 대본**을 따로 쓴다. 한 문장 25자 안팎, 한 장면 1~2문장.
- 모든 문장 해요체("~예요/~해요"). "~합니다", "~입니다" 금지.
- hook: 첫 2초 안에 이곳이 뭐가 다른지 한 문장. 사실만(과장·"역대급"·"꼭 가야 할" 금지). 질문형도 좋다.
- body: 그 장면 사진에 보이는 것을 말한다. 화면과 말이 어긋나지 않게.
- cta: 실용 정보 1개 + 확인 안내로 끝낸다. "구독·좋아요"는 넣지 않는다.
- 같은 어미·같은 연결어를 연달아 쓰지 않는다. 느낌표·이모지 없음(TTS가 이상하게 읽음).
- 바뀌는 정보(요금·시간)는 숫자를 말하지 말고 "가기 전에 확인하세요"로.
