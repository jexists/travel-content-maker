# 컨펌(승인) 진행 방법

승인은 **사용자(에디터)** 가 단계마다 하고, **대표(가상)** 는 채널마다 배포 직전에 한 번 한다. 승인 질문은 `tc.py review --stage …` 카드로 보여 준다.

| 순서 | 무엇 | 결정 | 기록 명령 |
| --- | --- | --- | --- |
| 인스타 1 | 사진 폴더 (AI 후보 / 내 폴더) | 에디터 | 진행 → `insta-use --dir insta_pick` / 싫다 → `insta-mine` → (사진 넣으면) `insta-use --dir insta_mine` |
| 인스타 2 | 표지 사진 (추천 1장) | 에디터 | 번호를 받음 ('다른 거' → 다음 후보 1장) |
| 인스타 3 | 표지 문구 | 에디터 | `insta-cover` → 미리보기 확인 |
| 인스타 4 | 올라가는 순서 | 에디터 | `insta-order` |
| 인스타 5 | 카드·캡션 | 에디터 | `confirm` / `reject --reason` |
| 각 채널 마지막 | 배포 | **대표** | `ceo --approve` / `ceo --reject --reason` |
| 유튜브·티스토리 | 결과물 | 에디터 | `confirm` / `reject --reason` |

## 원칙
- ⏸ 한 번에 **질문 하나**. 답을 받기 전에는 다음 단계로 가지 않는다.
- 사용자가 싫다고 하면 그 단계에서 멈추고 그 단계 안에서만 다시 제안한다(다음 단계를 미리 만들지 않는다).
- 내부 기술 사항(해상도, 코덱, 폰트 파일, 파일명 규칙)은 묻지 않는다. 기본값은 `settings.json`.
- 이미 승인된 단계(카드에 ✅)는 다시 묻지 않는다.
- 미리보기와 최종을 구분해서 말한다: `cover_preview.jpg`·컨펌 전 결과물은 "미리보기", 대표 승인된 버전만 "최종".
- 자동 점검이 실패한 결과물(`check_failed`)은 승인 요청을 하지 않는다. ❌ 항목을 먼저 고친다.
- 반려 사유는 해당 부분만 고친다(카드의 "고치면 바뀌는 범위"). 고친 뒤 새 버전 카드를 다시 보여 준다.
- "대표 승인/대표 반려"라고 말한 것만 대표 결정이다. AI가 대신 결정하지 않는다.
- 공유·발행 버튼은 사용자가 누른다. 결과물 위치는 `tc.py status`(→ `OUTPUTS.md`)로 보여 주고, ❌인 파일을 "완료"라고 말하지 않는다.
