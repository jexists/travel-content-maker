# 확인 지점 A~E (질문은 이 다섯 번만)

| 지점 | 카드 | 보내는 이미지 | 사용자 답 | 기록 |
| --- | --- | --- | --- | --- |
| A 브리프 + 인스타 | `review --stage brief` | `contact/A_insta_01.jpg` 1장 | `이대로` / 고칠 것 / `내가 고를게` | `build --ch instagram --confirm` (에디터 컨펌) |
| B 영상 제목·대본 (제작 전) | `review --stage script` | 없음 | `이대로` / 고칠 것 | `build --ch youtube --confirm` |
| C 블로그 제목 5개 + 내용 | `review --stage blog` | preview 캡처 1장 | `N번 제목으로 이대로` / 고칠 것 | `confirm --ch tistory` |
| D 대표 최종 승인 | `review --stage final` | 없음 (카드의 결과물 링크) | `대표 승인 전부` / 채널별 승인·반려 | `ceo --ch all --approve` 등 |
| E 링크 | `review --stage final` | 없음 | 링크 3개 한 메시지 | `publish-all` |

## 원칙
- 확인 지점 밖에서는 묻지 않는다. 기본값(`settings.json`)과 브리프로 정하고, 점검 실패는 고쳐서 다시 만든다.
- 한 지점에 질문은 1개, 이미지는 1장. 사용자가 한 메시지에 여러 수정을 주면 모두 반영하고 같은 지점을 다시 묻지 않는다(큰 변화만 다음 카드 앞에 한 줄로 알림).
- 사용자가 결정해야 하는 문제(사진 부족, 정보 충돌)만 다음 카드에 붙여서 말한다.
- 미리보기와 최종을 구분해서 말한다. D에서 대표 승인된 버전만 "최종".
- "대표 승인/반려"라고 말한 것만 대표 결정이다. AI가 대신 결정하지 않는다.
- 공유·발행·업로드 버튼은 사용자가 누른다. ❌인 파일을 완료라고 말하지 않는다.
