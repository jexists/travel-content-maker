# 컨펌(승인) 진행 방법

사용자에게 승인을 받을 때는 **항상 `tc.py review --stage …` 카드**를 보여 준다. 직접 질문을 지어내지 않는다.

| 순서 | stage | 결정하는 사람 | 기록 명령 |
| --- | --- | --- | --- |
| 1 | `photos` | 에디터(사용자) | 승인 → 다음 단계 / 변경 → selection.json 수정 후 `select` |
| 2 | `plan` | 대표(가상) | `plan --approve` / `plan --reject --reason` |
| 3 | `instagram` | 매니저(가상) | `confirm` / `reject --reason` |
| 4 | `youtube` | 매니저(가상) | `confirm` / `reject --reason` |
| 5 | `tistory` | 매니저(가상) | `confirm` / `reject --reason` |

## 원칙
- 한 번에 한 단계만. 카드의 "확인할 것"은 2~3개, 선택지는 카드에 적힌 것만.
- 내부 기술 사항(해상도, 코덱, 폰트 파일, 파일명 규칙)은 묻지 않는다. 기본값은 `settings.json`.
- 이미 승인된 단계(카드에 ✅ 표시)는 다시 묻지 않는다.
- 미리보기와 최종을 구분해서 말한다: 컨펌 전 결과물은 "미리보기", 컨펌된 버전만 "최종".
- 자동 점검이 실패한 결과물(`check_failed`)은 승인 요청을 하지 않는다. ❌ 항목을 먼저 고친다.
- 반려 사유는 해당 부분만 고친다(카드의 "고치면 바뀌는 범위"). 고친 뒤 새 버전 카드를 다시 보여 준다.
- 사용자가 결정한 말("매니저 컨펌", "대표 반려: …")을 그대로 기록 명령에 옮긴다. AI가 대신 결정하지 않는다.
- 결과물 위치는 `tc.py status`(→ `OUTPUTS.md`)로 보여 준다. ❌인 파일을 "완료"라고 말하지 않는다.
