# 02. 요구사항

> 여행 콘텐츠 3채널 제작 자동화 · v1.0 · 2026-11-09

## 1. 한 줄 정의

**사진과 메모를 넣으면 인스타그램 → 유튜브 숏폼 → 티스토리 순서로 콘텐츠가 만들어지고, 채널마다 매니저가 컨펌하고 대표가 최종 승인한 뒤, 모든 버전과 승인 기록이 콘텐츠대장에 남는다.**

발표 문장:
> 저는 **에디터(본인)**가 **여행을 다녀와 사진을 고르는 순간**부터 **인스타그램·유튜브·티스토리에 게시하는 것**까지 수행하는 **여행 콘텐츠 제작 업무**를 선택했습니다. 현재 **사진첩·지도 검색·인스타 앱·티스토리 에디터**를 쓰며, **같은 내용을 채널마다 다시 쓰고, 정해진 카드 표지를 매번 손으로 만들고, 유튜브는 손이 모자라 못 하는 불편**이 있습니다. 이번에는 **사진 한 번 입력으로 3채널 초안을 만들고 컨펌·승인 이력을 남기는 부분**을 개선하겠습니다.

## 2. 내가 말한 요구 (원문 요약)

대화에서 직접 말한 내용을 정리했다. 이 표가 아래 기능 요구사항의 출처다.

| U2 | 카드뉴스 형식으로 만들고 싶다. 지금 피드처럼 사진 위에 `#지역 #동네` 태그 + 큰 흰색 제목 형식이 정해져 있다 | FR-03 |
| U3 | 이미지가 모이면 숏폼으로 만들어 유튜브에도 올리고 싶다 | FR-05 |
| U4 | 사진을 보여 주면 **인스타 태그·글귀 → 유튜브 → 티스토리** 순서로 만들고 싶다 | FR-02~07 |
| U5 | 혼자가 아니라 **여러 사람이 일을 주고받는** 느낌으로, 중간에 **매니저가 컨펌**하고 **대표·플랫폼** 등으로 역할을 나누고 싶다 | FR-04·06·08·09, 역할 |

| U9 | 협찬 받는 과정도 궁금하다 (경험 없음, 조사 요청) | 범위 밖 (확장 자료로 정리) |

## 3. 결정 기록

| 날짜 | 결정 | 이유 |
| --- | --- | --- |
| 11-09 | 주제를 기획→PRD 대신 **여행 콘텐츠 제작**으로 | 인스타·티스토리를 실제 운영 중이라 As-Is를 설명할 수 있음 |
| 11-09 | **1안 · Claude 스킬 + 로컬 파일** | 입력이 로컬 사진, 결과가 이미지·영상·글 파일. 추가 비용 없음, 하루 안 구현 가능 |
| 11-09 | 채널 순서 **인스타 → 유튜브 → 티스토리** | 짧은 메시지를 먼저 확정하고, 승인된 카드로 숏폼을 만들고, 마지막에 긴 글로 확장 → 채널끼리 내용이 어긋나지 않음 |
| 11-09 | 역할 **대표·매니저·에디터** (가상 팀) | 컨펌·반려 왕복을 업무 흐름에 담기 위해. 실제는 1인 운영이므로 **가상 설정**으로 표시 |
| 11-09 | 매니저는 **채널마다 컨펌**, 대표는 **마지막 1회** 최종 승인 | 대표가 채널마다 보면 승인 대기가 6번 → 병목 |
| 11-09 | 플랫폼(인스타·유튜브·티스토리)은 승인자가 아니라 **게시 대상**(외부 채널 레인) | 플랫폼은 판단하는 주체가 아님 |
| 11-09 | 매니저 컨펌 앞에 **게시 규칙 자동 점검** 유지 | 매니저가 볼 항목이 줄고 누락을 막음 |
| 11-09 | 협찬·댓글 DM 자동화·KPI는 **제외** | 마감(11-10) 안에 핵심 흐름을 끝까지 작동시키는 것이 우선 |

## 4. 역할

| 역할 | 누구 | 하는 일 | 근거 |
| --- | --- | --- | --- |
| 에디터 | 본인 | 사진·메모 입력, 사실 확인, 업로드, 링크 입력 | 실제 |
| 매니저 | 가상 | 채널별 결과물 컨펌·반려(사유 작성) | 가상 설정 |
| 대표 | 가상 | 3채널 묶음 최종 승인·반려 | 가상 설정 |
| AI | Claude 스킬 | 사진·메모 해석, 채널별 문구·태그·제목·글 초안, 반려 사유 반영 | — |
| 시스템 | 스킬의 스크립트 | 카드 PNG·숏폼 MP4·블로그 HTML 생성, 규칙 점검, 버전 저장, 대장 기록 | — |
| 외부 채널 | 인스타·유튜브·티스토리 | 게시 대상 (자동 업로드 안 함) | — |

## 5. 기능 요구사항

| ID | 요구사항 | 담당 | 출처 |
| --- | --- | --- | --- |
| FR-01 | 입력 폴더(`input/C-001/`)의 사진과 `memo.md`를 읽는다. 사진이 없거나 메모에 장소명·지역이 없으면 **질문하고 멈춘다** | 시스템·AI | U4 |
| FR-02 | 사진·메모로 **인스타 카드 구성**(표지 + 본문 5~6장: 장마다 사진·문구), **캡션**, **해시태그**를 만든다. 메모에 없는 사실(가격·영업시간 등)은 지어내지 않고 "확인 필요"로 표시한다 | AI | U2·U4·U6 |
| FR-03 | 카드뉴스 PNG(1080×1350)를 템플릿으로 그린다. 표지는 사진 위 `#지역 #동네` + 큰 흰색 제목 | 시스템 | U2 |
| FR-04 | **매니저 컨펌 ①(인스타)**: 승인하면 다음 채널로, 반려하면 사유를 받아 같은 단계를 새 버전으로 다시 만든다 | 매니저 → AI·시스템 | U5 |
| FR-05 | 승인된 인스타 카드로 **유튜브 숏폼 MP4**(1080×1920, 15~30초)와 **제목·설명·태그**를 만든다 | 시스템·AI | U3·U4 |
| FR-06 | **매니저 컨펌 ②(유튜브)**: FR-04와 같은 방식 | 매니저 | U5 |
| FR-07 | 승인된 인스타·유튜브 내용을 길게 풀어 **티스토리 글**(HTML, 사진 배치 포함)을 만든다 | AI·시스템 | U1·U4 |
| FR-08 | **매니저 컨펌 ③(티스토리)**: FR-04와 같은 방식 | 매니저 | U5 |
| FR-09 | **대표 최종 승인**: 3채널 묶음을 한 번에 본다. 반려 시 채널과 사유를 지정하면 그 채널 단계로 돌아간다 | 대표 | U5 |
| FR-10 | 각 결과물을 만들 때마다 **게시 규칙 점검**을 실행하고 통과/실패표를 남긴다. 실패하면 컨펌으로 넘기지 않고 다시 만든다 | 시스템 | 결정 |
| FR-11 | **콘텐츠대장**(`ledger.xlsx`)에 단계마다 한 줄씩 기록한다: 콘텐츠ID·채널·버전·상태·담당·사유·결과 파일·일시 | 시스템 | U5 |
| FR-12 | 게시 후 에디터가 채널별 링크를 입력하면 상태를 **게시 완료**로 바꾼다 | 에디터 → 시스템 | U8 |

### 게시 규칙 (FR-10 점검 항목, `rules.json`)

| 채널 | 점검 항목 | 기준 |
| --- | --- | --- |
| 공통 | 장소명·지역 표기 | 세 채널 모두 같은 장소명 |
| 공통 | 금지 표현 | 예: "최고", "1등", "무조건" (팀 규칙으로 수정 가능) |
| 공통 | 협찬 여부 | `memo.md`에 `협찬: 예`면 광고 표시 필수 (인스타 첫 장 안, 유튜브 제목, 티스토리 본문 첫 줄) |
| 인스타 | 표지 태그 | `#지역 #동네` 2개 |
| 인스타 | 캡션 길이 | 2,200자 이하 (인스타 제한) |
| 인스타 | 해시태그 개수 | 5~15개 (팀 규칙, 인스타 제한은 30개) |
| 인스타 | 카드 장수 | 5~10장 |
| 유튜브 | 제목 길이 | 100자 이하 (유튜브 제한) |
| 유튜브 | 영상 길이·비율 | 15~30초, 9:16 (팀 규칙) |
| 티스토리 | 사진 수·소제목 | 사진 5장 이상, 소제목 3개 이상 (팀 규칙) |

## 6. 상태와 버전

- 상태: `초안` → `점검 통과` → `컨펌 대기` → `컨펌` / `반려` → … → `대표 승인 대기` → `대표 승인` / `대표 반려` → `게시 완료`
- 버전: 채널별로 `v1`, `v2`… 반려되면 새 버전을 만들고 이전 버전은 지우지 않는다.
- 대장 한 줄 = 한 사건(생성·점검·컨펌·반려·승인·게시). 지난 줄은 고치지 않고 아래에 추가한다.

## 7. 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-01 | Claude Code 스킬 + 로컬 파일. 추가 API 키·비용 없음 |
| NFR-02 | 다시 실행해도 이전 결과 폴더·대장 줄을 지우지 않는다 |
| NFR-03 | 같은 콘텐츠ID·채널·버전을 다시 생성하면 새 줄을 만들지 않는다 (중복 방지) |
| NFR-04 | 앞 채널이 컨펌되기 전에는 다음 채널을 만들지 않는다. 대표 승인 전에는 게시 완료로 바꿀 수 없다 |
| NFR-05 | 숫자·태그·제목 같은 글자는 템플릿으로 그리고 이미지 생성 모델을 쓰지 않는다 |
| NFR-06 | 예제는 내 여행 사진 또는 같은 구조의 가상 자료. 개인 연락처·위치 정보는 넣지 않는다 |

## 8. 수용 기준
