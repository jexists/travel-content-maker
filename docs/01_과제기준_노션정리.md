## 2. 과제 내용

- 본인이 잘 아는 업무 중 **아직 자동화되지 않은 업무 하나**를 골라, 현재 흐름을 분석하고 개선 프로세스를 **직접 구현**한다.
- 회사 전체가 아니라 **시작과 끝을 설명할 수 있는 작은 업무**로 정한다.
- 바다온수산이나 CRM을 그대로 만들 필요는 없다.
- 사람이 판단하거나 승인할 단계는 흐름에 넣는다.
- 예제 자료는 민감정보를 가리거나 같은 구조의 가상 자료로 준비한다.

## 4. 수업에서 가져온 작성 기준

### 2회차 · 분석 도구

| 도구 | 쓰는 이유 | 이 과제에서 |
| --- | --- | --- |
| 업무 설계 캔버스 | 목적·입력·작업·역할·판단·도구·예외·영향을 한 표로 | 04 문서 1-1 |
| 업무흐름도 (스윔레인) | 순서·분기·인계·되돌림·담당 구분. Draw.io로 작성 | 03 문서 + `diagrams/*.drawio` |
| 문제 카드 + 최소 기준선 | 사용자·상황·어려움·영향 / 근거 / 원인 가설 / 지표(실측·추정·가정·미확인) | 04 문서 1-3, 1-4 |
| RACI | 수행(R)·최종 책임(A)·협의(C)·공유(I). AI·시스템에 최종 책임을 주지 않음 | 04 문서 2-5 |
| 개략 시스템 구성도 | 입력 접점·AI 처리·규칙 처리·사람 승인·저장·외부 연결 | 03 문서 + `diagrams/architecture.drawio` |

- 근거 표시: 확인한 사실과 가설(H)·미확인(U)을 섞지 않는다.
- To-Be는 As-Is를 덮어쓰지 않고 별도로 두며, 활동마다 **유지 / 변경 / 이동 / 추가 / 제거**를 표시한다.
- 현재 AI를 쓰지 않는 업무에 As-Is부터 AI 레인을 넣지 않는다.

### 4회차 · 역할 구분 원칙

| 주체 | 맡는 일 |
| --- | --- |
| AI | 비정형 데이터 이해·생성 (해석, 초안, 설명) |
| 시스템 | 수식·코드로 정해진 처리 (계산, 검사, 파일 생성, 기록) |
| 사람 | 판단·승인, 고객과 소통 |

- 숫자·표·정해진 서식은 **템플릿으로 그리고**, 생성형 이미지 모델에 다시 그리게 하지 않는다.
- 차수(v1·v2)와 상태(작성·승인 대기·승인·생성 완료)를 나눈다. 승인과 파일 생성 완료는 다른 상태다.
- 변경이 생기면 이전 버전을 덮어쓰지 않고 새 버전으로 남긴다.
