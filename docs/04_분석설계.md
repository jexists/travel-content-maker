## 2. 개선 설계 (To-Be)

### 2-1. 문제별 개선 방향

| 문제 | 어떻게 바꿀까 (AI / 시스템 / 사람) | 어떻게 만들까 |
| --- | --- | --- |
| P1 | 시스템: 표지 템플릿으로 카드 PNG 생성 / AI: 장별 문구 / 사람: 컨펌 | HTML 템플릿 → Chrome 헤드리스로 PNG |
| P2 | AI: 승인된 앞 채널 내용을 다음 채널로 확장 / 사람: 사실 확인 | `content.json` 하나에 채널별 내용 누적 |
| P3 | 시스템: 승인된 카드로 숏폼 자동 생성 / 사람: 업로드 | ffmpeg로 카드 이어 붙이기 (9:16) |
| P4 | 시스템: 채널·버전별 폴더와 대장 기록 / 사람: 컨펌·반려 사유 입력 | `output/C-001/<채널>/vN/` + `ledger.xlsx` |
| P5 | 시스템: `rules.json`으로 자동 점검 / 사람: 규칙 수정 | 점검표를 결과 폴더에 저장 |
| P6 | 시스템: 게시 링크까지 대장에 기록 | 링크 입력 시 `게시 완료` |

### 2-2. 선택한 안 — 1안 · Claude 스킬 + 로컬 파일

| 비교 | 1안 스킬 + 로컬 ✅ | 2안 Notion/Sheets + 자동화 | 3안 자체 프로그램 + API |
| --- | --- | --- | --- |
| 사진 폴더 처리 | 바로 읽음 | 업로드·연동 필요 | 가능 |
| 카드 PNG·숏폼 생성 | 로컬 도구(Chrome·ffmpeg)로 가능 | 어려움 | 가능 |
| 채널별 컨펌 | 대화에서 바로 입력 | 체크박스로 가능 | 화면 개발 필요 |
| 비용·키 | 없음 | 없음 | API 키·사용료 |
| 하루 안 구현 | 가능 | 이미지·영상에서 막힘 | 빠듯함 |

**선택 이유**: 입력이 로컬 사진이고 결과가 이미지·영상·글 파일이라 파일을 직접 다루는 1안이 가장 자연스럽다. 컨펌·반려를 대화에서 바로 입력할 수 있고 추가 비용이 없다. 대장을 Excel로 두면 나중에 실제 팀이 생겼을 때 2안(Sheets·Notion)으로 옮기기 쉽다.

### 2-3. AI · 시스템 · 사람의 역할

| 주체 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| AI | 사진·메모 해석, 카드 구성, 캡션·해시태그, 유튜브 제목·설명, 티스토리 글, 반려 사유 반영 | 사실 확정, 컨펌·승인 |
| 시스템 | PNG·MP4·HTML 생성, 규칙 점검, 순서 강제, 버전 저장, 대장 기록·중복 방지 | 문구 창작 |
| 에디터 | 사진·메모 입력, 사실 확인, 업로드, 링크 입력 | 매번 카드 수작업·재작성 |
| 매니저 | 채널별 컨펌·반려(사유) | 직접 수정 |
| 대표 | 3채널 묶음 최종 승인·반려(채널·사유) | 채널별 세부 검토 |

| 인스타 초안·카드 (T02·T03) | — | I | A | R | R |
| 컨펌 ① 인스타 (T04) | I | R·A | C | — | — |

### 2-8. 대표 입출력 예시

- **입력**: `input/C-001/` — 동막해변 사진 6장 + `memo.md`
  ```
  장소: 동막해변
  지역: 인천 / 강화도
  한 줄: 겨울에만 볼 수 있는 얼어붙은 갯벌
  메모: 바다가 얼음 조각으로 덮여 있음, 바람이 세서 오래 있기 힘듦, 근처 주차 가능
  협찬: 아니오
  ```
- **출력**:
  - `output/C-001/instagram/v1/`: `card_01.png` ~ `card_06.png`, `caption.txt`, `check.md`
  - `output/C-001/youtube/v1/`: `shorts.mp4`, `meta.txt`(제목·설명·태그), `check.md`
  - `output/C-001/tistory/v1/`: `post.html`, `check.md`
  - `ledger.xlsx`: 생성·점검·컨펌·승인·게시 줄
- **반려 예**: 매니저 "표지를 얼음 클로즈업 사진으로" → `instagram/v2` 생성, 대장에 사유 기록

## 부록. 협찬 흐름 조사 (확장 아이디어)

이번 범위에서는 제외했지만 다음 단계로 확장할 때 참고한다. 모두 조사 기반 가설(H).

- 시작은 **체험단 플랫폼 신청**(광고주 공고 → 신청 → 선정) 또는 **직접 제안**(제안서 + 레퍼런스 전송). 경험이 없으면 체험단으로 포트폴리오를 쌓은 뒤 제안하는 순서가 권장된다.
- 선정 후: 조건 협의 → 가이드라인(필수 키워드·해시태그·사진 장수·금지 표현·기한) → 방문 → 원고 → 광고주 검수·수정 → 게시 → 결과 보고.
- 무료 제공·원고료 등 **경제적 이해관계는 반드시 표시** (공정위 추천·보증 심사지침). 블로그는 본문 처음 또는 끝, 사진 SNS는 사진 안, 동영상은 제목 또는 시작·끝. "광고·협찬·유료 광고"처럼 알아보기 쉬운 한국어로. ⚠️ 언론 보도 기준, 원문 확인 필요.
- 이번 설계에 남겨 둔 연결점: `memo.md`의 `협찬: 예` → 광고 표시 점검 (02 요구사항 게시 규칙).
